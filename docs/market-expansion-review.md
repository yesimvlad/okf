# Market expansion source and review notes

Expanded AR, ZH-CN, ID, RU, PT, PT-BR, ES, IT, CS, JA, FR, DE and VI using the detailed PL/RO approach. Each file contains product distinctions, selection/installation/validity routing, local terminology, four destination sources, travel/number scenarios, ten localized answer patterns, 14 general query candidates, four destination queries, article proposals, claim controls and a review queue.

## Evidence and limits

The 130 localized sources listed below were retrieved through web lookup on 2026-10-08 (13 × home, Pay & Fly, number overview, compatibility, regional, global and four country pages). Retrieved text can come from cached crawls. This is source availability/content routing evidence, not an HTTP, canonical/hreflang, full translation or app test. Current checkout and Product Descriptions control mutable conditions.

Query phrases, terminology and scenarios are newly authored editorial drafts. No GSC/Ahrefs exports or traveller analytics were supplied for this expansion; no query volume, popularity ranking, market share or projected traffic is invented. Native-language and product-owner approval remain pending. All 13 files remain draft and excluded from verified export.

## Specific findings

- RU: eSIM/destination/compatibility routing uses `yesim.tech/ru/`; number overview uses `yesim.app/ru/virtual-number/`. The retrieved .tech navigation lists data and Pay & Fly but not the virtual-number product. Language presence must not establish regional eligibility. Canonical/mirror handling remains a separate production audit.
- ES, FR, JA, VI: retrieved Pay & Fly titles retain unlimited-data wording, while payment descriptions support usage billing. File answers use data-consumption billing and distinguish Unlim Day Pass; production titles are unchanged.
- PT versus PT-BR: retain separate editorial vocabulary and source routing. PT needs native review for mixed Portuguese wording. Brazilian payment/tax conditions must not be inherited by PT.
- PT-BR: the shared refund source includes a Brazil/Pix and IOF clause. Link current policy without hardcoding a tax percentage or inferring Pix eligibility for all customers.
- ZH-CN: exact device sales-region variants must be checked; do not copy outdated blanket statements about China-sold device families.
- AR: review RTL display with LTR product names, model codes, units and links on production.
- VI: use language code `vi`; `vn` in the request refers to Vietnamese audience, not a website locale slug.
